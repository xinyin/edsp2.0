# 平台响应字段赋值

在“标准服务开发 → 字段标准化 → 响应标准化”中配置响应映射。

| 需求 | 响应来源 | 来源字段 / 值 | 目标路径 | 处理方式 |
| --- | --- | --- | --- | --- |
| 使用上游返回码 | 指定字段 / 对象 | `$.result.code` | `$.code` | 直接映射 |
| 使用上游提示信息 | 指定字段 / 对象 | `$.result.message` | `$.message` | 直接映射 |
| 使用固定提示信息 | 固定值 | `处理成功` | `$.message` | 固定赋值 |
| 完整保留上游响应 | 完整供应商报文 | 无需填写 | `$.data` | 原样复制 |
| 将上游对象放到指定节点 | 指定字段 / 对象 | `$.support` | `$.payload.support` | 直接映射 |

目标路径以 `$.` 开头表示平台响应根节点。为兼容已有配置，不带 `$.` 的普通路径仍写入 `data` 下，例如 `code` 表示 `data.code`，与 `$.code` 不同。

## 默认值与校验

- 未配置 `$.code` / `$.message` 时，沿用统一返回码规则和平台默认提示信息。
- 可选来源缺失或为空白时，沿用平台默认值；配置默认值时优先使用该默认值。勾选必填后，来源和默认值均为空会报错。
- `code`、`message` 只接受文本、数字或布尔值，最终输出为文本。不能写入对象、数组，也不能配置 `$.code.detail` 等子路径。
- `traceId`、`resultStatus` 等运行字段由平台维护，不允许通过响应映射覆盖。
- 同一目标路径及父子路径不能重复赋值，例如不能同时配置 `$.data` 和 `$.data.items`。

## 返回值与业务判定

输出 `code` / `message` 的赋值不改变业务结果判定。是否命中、是否纳入对账量，仍由“结果码映射”规则决定。有效的上游业务响应即使判定为 MISS 或 ERROR，仍可提取上游 code/message；命中业务数据的映射保持原有仅在 HIT 时执行的逻辑。

例如，上游 `result.code` 为 `200`，统一返回码规则将其判定为 HIT；可以将输出 `$.code` 设置为上游 `200`，平台仍按 HIT 处理。调用记录和计量记录中的 `standard_code` 与最终输出码保持一致。

保存后执行链路测试，确认实际报文。结构预览支持直接映射、固定值、枚举和返回码判定；日期及安全算法结果以链路测试为准。修改已上线服务的草稿后，需要上线新版本才会影响线上调用。
