# 发布前验证与版本管理

更新日期：2026-10-14。

## 开发与发布流程

1. 在“上游能力接入”保存资源 API 的地址、请求和响应样例，并验证资源接口。
2. 在“标准服务开发”基于资源 API 创建标准服务。资源接口后续发生变更时，点击“同步资源契约”，明确将最新契约接入当前草稿。
3. 核对行内标准请求、请求映射、响应映射、返回码和安全策略，保存草稿。
4. 可选执行“草稿链路测试”，真实请求上游并检查转换结果。测试结果不影响进入发布或上线。
5. 在“服务发布”完成必要配置校验后上线，然后在“API 访问授权”配置调用系统的授权。
6. 可选执行“上线链路测试”：通过 XML → 模拟 ESB → Adapter → Gateway → 管理端草稿执行器 → 数据源应用 → 真实上游 → XML，测试当前已保存草稿。未发布、已发布、有新草稿和已下线接口均可使用，不要求业务 API 授权。

草稿链路测试、上线链路测试与上线操作相互独立。上线只要求配置校验通过，不要求任何链路测试记录。名称中的“上线链路”指经过 ESB/Gateway 的测试路径，不表示必须先上线，也不是线上已发布快照的验收入口。

## 两种验证的边界

| 模式 | 实际执行路径 | 发布前是否必须 | 是否需要上线和调用方授权 |
| --- | --- | --- | --- |
| 草稿链路测试 | 保存的标准请求 → 管理端公共组件执行映射/安全策略 → 独立数据源应用 → 真实上游 → 返回码处理/响应标准化 | 否 | 否；仍由管理端访问权限保护 |
| 上线链路测试 | XML → ESB Adapter → Gateway → 管理端草稿执行器 → 数据源应用 → 真实上游 → ESB Adapter → XML | 否 | 否；需要操作员登录会话与服务端内部测试凭证 |

草稿链路测试使用管理端编排、独立数据源应用负责出站调用的草稿执行入口。它不会激活发布计划，也不改变线上路由。它不经过 ESB/Gateway，不能替代这两层的队列、路由、鉴权验收。链路记录中 Gateway 标为 SKIPPED。

当前草稿出站入口沿用 HTTP POST/JSON 能力；其他供应商协议/方法以及应用专属插件仍需扩展对应执行入口，并验证与线上执行行为一致。两种工具测试均不激活发布计划或改动正式授权，因此不能代替正式授权调用的验收。

## 测试入口和访问边界

页面调用 `POST /api/test-tools/chain`，携带登录后签发的 `X-Edsp-Operator-Token` 与同源会话 Cookie。管理端校验会话后，将 XML 发往 Adapter，并由服务端附加 `X-Edsp-Internal-Test-Key`。该凭证不发送到浏览器。

Adapter 对 `diagnostic=true` 强制检查内部凭证；仅在检查通过后，才注入 `DRAFT_TEST` 执行域。Gateway 再次检查凭证，将请求发往管理端 `/api/internal/test-chain/{apiCode}`，无需读取发布路由或业务授权。管理端按 API 编码读取当前已保存草稿，由对应独立数据源应用调用真实上游。

公开 `/esb/queue/request` 的正式请求不携带诊断参数，继续执行已发布路由和 API 授权检查。外部调用方不能仅凭 `diagnostic=true` 切换为草稿执行。

管理端会话空闲有效期为 30 分钟，重启管理端后需重新登录。多实例生产部署需使用统一操作员身份/会话方案。三个服务必须设置相同的独立 `EDSP_INTERNAL_TEST_KEY`；配置模板中的默认值仅供本地使用，生产环境通过密钥管理注入。

XML 的 `service_sn` 贯穿测试执行与记录。节点明细返回真实的上游请求、响应及执行状态；队列等待、XML 解析、Gateway 往返与 XML 封装分别计时。Gateway 往返包含内部编排和上游调用耗时，不应与内部节点耗时相加计算总耗时。失败时返回已记录的异常节点及 Trace ID。

## 资源契约同步

标准服务保存的是资源契约的草稿副本，不会因资源 API 被编辑而自动修改线上发布快照。

`POST /api/interfaces/{id}/sync-resource` 更新草稿的上游地址、路径、配置继承方式、超时、请求样例和响应样例。已有字段映射、返回码和安全策略保留。

- 请求方向没有映射，且标准请求样例仍等于旧上游请求样例时，标准请求样例一起更新，保持透传。
- 响应方向没有映射，且标准响应样例仍等于旧上游响应样例时，标准响应样例一起更新。
- 已定制的行内契约保持原样，由开发者调整与新上游契约之间的映射。
- 同步后旧测试结果失效；是否重新测试由开发人员按风险决定，不影响上线。
- 已发布路由、执行计划及其快照不受同步影响。

若资源接口将 `query_key` 改为其他字段，先同步资源契约，再核对标准请求与映射。不能通过删除上线校验来绕过供应商的必填约束。

## 校验与凭证

之前的 PLATFORM 测试只装载上游响应样例，可能出现样例测试通过、上线请求契约校验失败。现在 PLATFORM 表示真实的发布前业务链路验证，不再使用客户端提供的模拟响应。

草稿链路测试和上线前配置校验使用同一套请求契约规则：字段映射和安全处理后的上游请求必须满足已保存的上游样例契约。目前仍是样例驱动规则：样例中的字段视为必填并检查 JSON 类型，尚不是带可选字段声明的完整 JSON Schema。

测试请求和映射必须与保存的草稿一致。上游传输失败、返回码未匹配、业务结果为 ERROR、响应转换异常或测试期间配置改变时，测试失败，但不改变草稿是否允许发布。

凭证存储在现有 `interface_validation_record` 表，草稿链路测试类型为 `DRAFT_TEST`，绑定配置的 SHA-256 摘要。摘要包含请求、响应契约、映射、安全策略、结果码、地址、超时及候选版本等；排除状态、更新时间和已发布版本字段，避免仅因进入审批流程而失效。

每次保存草稿都会删除旧的 ORCHESTRATION/PRE_RELEASE/DRAFT_TEST 测试状态。上线、提交审批和审批通过均不检查这些测试记录；必要的静态配置校验仍会执行。失败调用仍记录节点日志。

## 版本规则

旧实现中，保存映射、结果码、安全策略、连接配置分别执行 `current_version + 1`。因此 V1 → V6 可能只是保存了五次配置，并非上线了五次。

新规则将标准服务的 `current_version` 作为待发布版本：

| 操作 | current_version | published_version |
| --- | --- | --- |
| 创建服务、首次发布前反复保存 | 1 | 空 |
| 首次上线 | 1 | 1 |
| 编辑已上线 V1，首次保存 | 2 | 1 |
| 同一草稿再次保存映射/安全策略/返回码 | 2 | 1 |
| 验证通过并上线 | 2 | 2 |
| 再次编辑并保存 | 3 | 2 |

保存草稿使用 `COALESCE(published_version, 0) + 1`。验证不增加版本。保存次数不再作为发布版本数；是否需要重新验证由凭证与配置摘要控制，不能仅比较版本号。

历史已发布 V6 保留 V6，后续草稿为 V7，不重排历史发布记录。旧逻辑产生、尚未发布的 V6 草稿，在下一次保存或同步资源契约时归一为“已发布版本 + 1”（如已发布 V1，则为 V2）。未修改的历史草稿不在后台自动批量改号。

资源 API 的 `current_version` 仍表示资源配置修订次数，和标准服务发布版本是两种生命周期，不能用资源修订次数解释标准服务的上线次数。

## 下线与重新上线

下线会删除 Gateway 发布路由、撤销数据源应用中的活动执行计划并保留发布快照、版本历史、授权和调用日志。

下线只改变线上运行状态，不关闭服务开发能力。已下线接口仍可在“标准服务开发”中编辑并保存连接、字段映射、返回码和安全策略；首次保存形成“已发布版本 + 1”的草稿版本，同一草稿反复保存不继续递增，接口保持 `OFFLINE`，不会因此恢复 Gateway 路由或生产流量。

当已下线接口同时存在旧线上版本和新草稿时，发布管理提供两个独立动作：

- “恢复线上 Vx”恢复最近一次已经发布的不可变快照，不带入新草稿。
- “上线草稿 Vy”发布当前草稿，以新版本替换生产执行计划并恢复流量。

发布管理中的“恢复线上 Vx”只恢复最近一次已经发布的不可变快照，不把当前草稿当作线上版本。例如线上 V2 下线前已经形成 V3 草稿，恢复后 Gateway 和数据源应用继续运行 V2，V3 草稿保留，之后可另行发布。恢复不增加版本号，原有有效授权重新具备调用条件。

如果历史接口缺失 V2 发布快照，但当前表中已经存在 V3 草稿，平台拒绝使用 V3 覆盖恢复 V2，避免未发布配置意外进入生产。此类旧数据需要先补齐历史发布快照。

## 部署与回归

没有新增数据库表或字段。需要更新 Admin、Gateway、ESB Adapter 和前端，并同步对应 Nacos 配置；Gateway 管理端路由需包含 `/api/test-tools/**`。重载后刷新前端并重新登录；现有测试数据不重置。

回归重点：上游字段变更后的契约同步；映射遗漏必填字段时验证直接失败；草稿验证真实调用数据应用且忽略模拟响应；上游错误与并发修改不能签发凭证；反复保存不跳版本；保存后凭证失效；已发布快照保持独立。
