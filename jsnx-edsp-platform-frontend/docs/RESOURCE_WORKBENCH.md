# 数据资源服务：向导与目录优化

## 页面变化

- 资源目录不再被内部固定高度裁断；长名称、编码换行显示，随页面滚动完整访问。
- 默认展开当前数据资源，可单独折叠、展开 / 收起全部和定位当前 API。搜索时自动展开匹配结果，清空搜索恢复折叠偏好。
- 请求超时收进按需展开的配置区。新增 API 默认继承数据资源；已有单接口覆盖值保留，不因折叠或打开页面而改变。
- 操作统一到页底：上一步、保存当前步骤、保存并继续 / 下一步。无修改时下一步不会重复保存、增加版本。
- 操作说明可收起；每一步给出目标、操作顺序和注意事项。

## 首次配置一个接口

1. 左侧选择数据资源，新增 API 并核对行内服务路径、上游基础地址及接口相对路径。
2. 定义接口：查看最终上游地址；只有特殊超时需求才展开请求超时并选择单接口覆盖。
3. 字段标准化：请求页粘贴行内 JSON 样例，生成映射并核对供应商目标字段；响应页粘贴供应商样例，映射到平台标准字段。样例生成不会自动理解业务语义。
4. 统一返回码：配置原始码、平台码、HIT / MISS / ERROR 语义，以及重试和计费标识。
5. 安全策略：普通接口保持关闭直接继续；有加密或签名要求时使用已实现的能力。演示算法不是生产安全承诺。
6. 联调验证：可先做上游连通性和平台适配，最后执行完整链路测试，点击节点核对实际报文。
7. 审批上线：查看发布前检查、填写变更说明、校验并提交审批。提交不等于上线；在审批中心通过后才激活版本。
8. 服务授权：为机构 / 调用系统授权；已有授权无需重复创建。通过正式调用链验证，并到调用日志核对结果。

## 状态与数据保护

- 保存失败、样例 JSON 不合法时保留编辑内容并停留当前步骤。
- 放弃修改后会真正还原已保存内容；取消离开则保留当前编辑。
- 向导提示分别检查请求、响应映射，不将一侧映射当成两侧都已完成。
- 安全策略是可选步骤；未启用不表示配置异常。
- 本次会话的完整链路通过记录绑定接口 ID 和草稿版本。上游单测、平台适配测试、旧版本成功都不能代替当前版本完整链路验证。
- 完整链路再次失败时撤销本次会话通过标识；刷新页面后需重新验证。
- 上述联调标记是前端辅助信息，并非后端持久化发布门禁。直接跳转发布时会提示缺少验证记录；最终配置校验及审批规则仍由后端负责。
- 特殊透传场景可直接切换步骤，是否允许发布以实际后端校验为准。

## 验证方式

运行 npm run test:resource 执行本地逻辑回归，运行 npm run build 执行 TypeScript 与生产构建检查。

浏览器人工验收：

- 使用多个数据资源和长 API 名称，检查目录最底部条目可见、搜索和折叠正常。
- 分别选择继承超时 / 已有独立超时的接口，确认初始折叠、摘要准确，展开或收起不产生未保存修改。
- 逐步完成向导；尝试无效 JSON、保存接口失败、取消 / 放弃修改，检查不错误跳步或丢失编辑。
- 上游单测之后不应提示完整链路通过；修改已验证的配置并保存后，旧版本测试记录不能继续用于当前版本。
- 提交后显示等待审批，审批通过并刷新后显示当前版本已发布和服务授权入口。

本次不改数据库结构，不修改既有请求超时数据，不新增后端发布限制。
