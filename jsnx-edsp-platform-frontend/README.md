# EDSP 2.0 平台前端

独立 Vue 3 + TypeScript + Element Plus 工程，开发端口 `5173`。前端只负责平台运营工作台，不包含供应商应用页面。

## 功能模块

- 运营总览：调用量、成功率、计量金额与数据源登记情况。
- 资源目录 / 资源方管理：发现资源方开放能力，维护提供商资料、账号和权限。
- 上游能力接入：按“连接配置 → 请求与响应 → 接入验证”维护资源 API。
- 标准服务开发：从已保存资源创建平台服务，配置字段、返回码、安全策略，按需联调。
- 服务发布：上线、下线、版本档案；缺少处理应用地址时可直接进入运行路由配置。
- API 访问授权：登记调用系统、单个或批量授权、配额管理；清单支持系统筛选、关键词检索与分页。
- 计量管理：计量规则、调用明细和费用汇总。
- 链路追踪 / 运行监控：检索 Trace ID、查看节点报文、耗时和告警。

## 接入到上线的操作顺序

1. 在“资源方管理”登记提供商，在“上游能力接入”创建数据源。基础地址填写供应商地址；处理应用路由是行内数据源应用地址，两者不能混用。运行路由可稍后填写，但上线前需要配置。
2. 选择数据源，新增资源 API；配置相对路径或完整地址，默认继承数据源超时。第二步维护供应商实际请求与响应样例。步骤间切换保留输入，点击“保存上游配置”才持久化。
3. 第三步可以真实调用上游验证。验证不是创建或上线的强制条件，也不会仅凭 URL 格式宣称 TLS 或网络校验成功。
4. 保存配置后点击“创建标准服务”。原始报文成为标准契约的起点；不需要转换时保留空映射，平台按原字段透传。
5. 在“标准服务开发”依次设置字段标准化、统一返回码、可选安全策略与可选链路测试。“保存并继续”仅在当前步骤保存成功后进入下一步；直接切换步骤或模块会提示未保存修改。
6. 进入“服务发布”上线，再进入“API 访问授权”为调用系统授权。测试与发布独立，草稿与线上版本仍分别管理。

## 前端维护约定

- `src/App.vue`：上游能力接入与标准服务开发采用 API 工作台布局；发布、授权由独立模块承接。
- `src/console-theme.css`：统一控制台色彩、表单、表格与响应式布局；在历史功能样式之后加载。新增视觉规范集中维护于此。
- `src/composables/useDisplayPreference.ts`：仅在本地保存菜单和目录折叠偏好，不保存业务草稿或凭据。
- `src/resource-guide.ts`：步骤状态和校验逻辑；`tests/resource-guide.test.mjs` 覆盖保存失败、透传、未保存导航保护等行为。
- 授权清单目前为已加载数据的前端过滤与分页，不等同于后端分页。大规模数据集需配合后端分页接口进一步扩展。
- 构建校验：`npm run build`；流程回归：`npm run test:resource`。

## 运行模式

- `VITE_DEMO_MODE=mock`：不依赖后端，可演示页面交互。
- 默认模式：通过 `/api` 调用平台后端，通过 `/vendor-api` 调用供应商应用。

```bash
npm install
npm run dev
npm run build
```
